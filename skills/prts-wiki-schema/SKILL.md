# PRTS Wiki 资料结构与字段索引

本地 `reviewed_wiki` 资料不是同质文本，而是具有严格模式结构（Schema）的语义骨架。**严禁在没有过滤条件的情况下直接搜索整个 `reviewed_wiki`**，应当优先根据目标问题选择对应的 Wiki 类型与具体字段。

---

## 一、三类 Wiki 页面结构与定位方式

### 1. 规范角色页：`character_wiki`
- **定位方式**：必须搭配 `character_names: ["干员或角色名"]` 精确定位。一名角色仅有一页。
- **支持的 `wiki_sections` 标签字段**：
  | 字段名 | 核心内容 | 最佳适用场景 | 证据性质 |
  | :--- | :--- | :--- | :--- |
  | `简要介绍` | 身份、阵营、核心背景与关键经历短概览 | 回答“这个人是谁”、“是什么身份” | 事实概括 |
  | `相关角色` | 主要人物关系表及关系性质描述 | 梳理人际关系、阵营纽带的入口 | 关系线索 |
  | `详细介绍` | 跨活动的完整生平经历、立场演化与阶段变化 | 人物长篇生平考证、行为动机分析 | 完整梳理 |
  | `剧情高光` | 重要场面、决战节点及对应的出处章节 | 快速发现值得回查的剧情篇章 | 导航线索 |
  | `战斗表现` | 角色战斗能力、法术特性与战术表现总结 | 战力评估、设定考证 | 设定提炼 |
  | `相关活动` | 角色登场或参与过的全部活动清单及其所起作用 | 考证“某人参加过哪些活动”的首选入口 | 参与清单 |
  | `trivia` | 杂谈、冷知识、姓名考据与设计细节 | 设定细节、原型考据 | 整理参考 |
  | `角色点评` | 针对角色的综合主观评价与玩家社区视角 | 仅供参考，**严禁当作官方明示事实** | 主观评价 |

---

### 2. 活动／密录页：`story_wiki`
- **定位方式**：必须搭配 `activity_names: ["活动展示全名"]`（如 `["孤星"]`、`["巴别塔"]`）；干员密录也沿用其故事展示名。
- **支持的 `wiki_sections` 标签字段**：
  | 字段名 | 核心内容 | 最佳适用场景 |
  | :--- | :--- | :--- |
  | `剧情总结` | 整部活动、主线篇章或密录的起因、发展脉络与最终结局 | 快速掌握整部剧情主旨大意与走向 |
  | `关键人物` | 出场的核心人物清单及其阵营分布 | 快速建立后续查询的人物范围 |
  | `角色剧情概括` | 逐个角色说明其在该活动中的行动路线与所起作用 | 回答“某人在该活动中做了什么”、“起到了什么作用” |
  | `剧情高光` | 代表性高潮场面提炼与代表性表达 | 快速定位核心对峙篇章 |
  | `trivia` | 活动中的隐藏设定细节与轶事 | 世界观细节补充 |

---

### 3. 角色×活动交叉辅助页：`character_activity_wiki`
- **定位方式**：同时指定 `character_names: ["角色"]` 与 `activity_names: ["活动"]`。
- **包含字段**：`相关剧情总结`、`相关剧情高光`、`相关trivia`、`相关角色总结`。
- **定位与地位**：这是生成规范角色页时的底层辅助整理材料，适合补充具体行动过程，但其证据权威性低于规范角色页与活动页，更不能替代官方剧情原文。

## 二、结构化单字段精准提取指南（核心效能范式）

如果只需要角色的某个具体字段（如“简要介绍”或“相关活动”），**严禁进行长文本全文检索**，应当采用以下两种零浪费、免超时的单字段提取方式：

### 方式 A：通过 `prts_search` 提取字段（推荐）
- **核心操作**：**省略 `query`**，指定目标角色/活动，指定单个 `wiki_sections`。
- **示例 1：提取凯尔希的简要介绍**
  ```json
  prts_search({
    "games": ["arknights"],
    "resource_types": ["character_wiki"],
    "character_names": ["凯尔希"],
    "wiki_sections": ["简要介绍"]
  })
  ```
  *效果*：直接返回整段“简要介绍”，不会被长文本中其他章节的同词淹没。
- **示例 2：提取巴别塔活动的剧情总结**
  ```json
  prts_search({
    "games": ["arknights"],
    "resource_types": ["story_wiki"],
    "activity_names": ["巴别塔"],
    "wiki_sections": ["剧情总结"]
  })
  ```
- **示例 3：提取特蕾西娅在巴别塔活动中的表现**
  ```json
  prts_search({
    "games": ["arknights"],
    "resource_types": ["story_wiki"],
    "activity_names": ["巴别塔"],
    "wiki_sections": ["角色剧情概括"],
    "query": "特蕾西娅"
  })
  ```

### 方式 B：通过 `prts_read` 直读字段
- **核心操作**：指定标题与目标 `section` 字段名。
- **示例**：
  ```json
  prts_read({
    "title": "凯尔希",
    "section": "简要介绍"
  })
  ```

## 三、证据地位与回答界限

1. **可直接作为回答证据的场景**：
   - 角色身份概括（来自 `简要介绍`）；
   - 人物参与过的活动清单（来自 `相关活动`）；
   - 活动整体起因与结局概括（来自 `剧情总结`）。
2. **必须回读官方原文（`story`/`operator_record`）的场景**：
   - 用户明确要求精准原句台词或谁亲口说的；
   - 用户询问某句话是在什么具体动作、神态或场景下说出的；
   - 用户需要完整的剧情上下文或行号引用（如《展示标题》第 N 行）。
   - Wiki 整理材料中带引号的台词可能存在转述或轻微省略，实质争议时永远以原文为最终基准。
