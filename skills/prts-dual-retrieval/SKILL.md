# 双游戏联合检索与跨世界观考据配方

本技能适用于同时涉及《明日方舟》与《明日方舟：终末地》两款游戏对比、再旅者（Retraveler）身份溯源、跨世界观概念迁移以及归属未知的考据问题。

---

## 一、双模块联合检索核心准则

1. **按需激活，拒绝无端双搜**：
   - 双游戏资料库同时启用，**绝不代表每个问题都要同时搜索两边**。
   - 问题已明确属于单款游戏时，必须只传对应的单个 `games: ["arknights"]` 或 `games: ["endfield"]`，彻底防止同名角色与相似设定的串库干扰。
   - 只有当问题明确要求横向对比、询问跨游戏联系，或实体归属确实完全未知时，才使用双模块联合调用。
2. **联合宽搜 vs 独立窄检索**：
   - `games: ["arknights", "endfield"]` 适合作为首次探索的“联合宽搜”；
   - 一旦进入正式取证环节，**必须拆分为两个独立的单游戏调用**，分别使用各自模块合法的资料类型进行核验，最后合并结论。严禁使用同一套 `resource_types` 数组强行套用两边。
3. **跨游戏事实与推断分离**：
   - 跨游戏回答必须分别列出“方舟侧资料明示的事实”与“终末地侧资料明示的事实”；
   - 跨游戏相似点与差异分析属于大模型的综合推断，严禁把推断伪装为任一侧的官方原文明示。

---

## 二、再旅者（Retraveler）与泰拉记忆原型考证铁律

当用户询问终末地角色与方舟角色的联系、原型或“是不是同一个人”时，必须严格遵守以下审校纪律：

1. **`retraveler_relations` 人工审校字段性质**：
   - 在终末地角色资料检索中，结果可能包含 `retraveler_relations` 字段。
   - **权威性与边界**：该字段属于 **PRTS 人工审校的关系登记**。它可以直接支持“该角色在 PRTS 审校登记中对应的泰拉记忆原型为某干员”这一有限结论，**回答时必须显式注明此为资料登记性质**。
2. **严禁脑补与过度外推**：
   - 登记关系**绝不等于官方剧情已正式确认两者为同一个具体人物**；
   - **绝不能**据此直接断言两者共享记忆、灵魂转世、或是剧情上已正式认亲；
   - 对双方的具体身份、经历与表现，必须分别检索两侧的角色档案独立表述。
3. **未登记时的无证据判定**：
   - 若检索结果不带 `retraveler_relations`，仅凭外观相似、配音相同、姓名接近或类似武器道具，只能客观陈述：“设定与外观存在相似性，但当前官方资料与审校登记中尚未确认正式关系”；
   - **严禁**自行替官方设立别名或硬性建立前世今生关系。

## 三、跨游戏考据四大标准流程

### 1. 概念或人物跨游戏对比
1. **第一步（界定维度）**：明确对比维度（如“天灾与侵蚀”、“萨卡兹与天使”、“凯尔希与再旅者”）。
2. **第二步（方舟侧独立取证）**：
   ```json
   prts_search({
     "games": ["arknights"],
     "resource_types": ["story", "character_profile", "terra_journey"],
     "query": "方舟目标概念"
   })
   ```
3. **第三步（终末地侧独立取证）**：
   ```json
   prts_search({
     "games": ["endfield"],
     "resource_types": ["original_story", "archive", "knowledge"],
     "query": "终末地目标概念"
   })
   ```
4. **第四步（综合归纳）**：分别引用两款游戏各自的官方原文与档案出处，再进行客观横向对比。

---

### 2. 再旅者原型考证配方
1. 输入再旅者名称，在终末地侧检索角色档案：
   ```json
   prts_search({
     "games": ["endfield"],
     "resource_types": ["archive", "character_story"],
     "character_names": ["再旅者角色名"]
   })
   ```
2. 检查返回结果的 `retraveler_relations`：
   - 若存在：提取登记的泰拉原型干员名，据此向方舟侧查询该干员资料，回答时说明“PRTS 人工审校关系登记显示其原型为……”；
   - 若不存在：分别检索双方资料，仅对比客观设定，指出缺乏官方正式确凿联系。

---

### 3. 不确定实体归属哪款游戏时的定位配方
1. 以短字面量进行联合搜索：
   ```json
   prts_search({
     "games": ["arknights", "endfield"],
     "query": "未知实体名称"
   })
   ```
2. 观察返回每篇结果的 `game` 字段：
   - 确认其实体所属的主游戏模块；
   - 一旦确认归属，立即切换为单游戏检索深入查证，剔除另一侧无关干扰。

---

## 四、单侧缺失与时间线对照边界

1. **单侧无结果的处理**：
   - 联合检索中若只有一边有结果，检查是否是因为另一侧未安装对应语料包（如 `CORPUS_GAME_NOT_INSTALLED`），或使用的 `resource_types` 属于单方独有；
   - 排除故障后若确实无结果，必须客观说明：“该概念在《XX》中有记载，但在《YY》当前资料中未检索到相关记录”，**切勿用单侧信息臆断另一侧情况**。
2. **时间线跨游戏对照铁律**：
   - 方舟侧使用 `prts_timeline` 或 `story` 构建时间；
   - 终末地侧使用 `resource_types: ["timeline"]` 或 `original_story` 构建顺序；
   - 必须先在各自世界观内部建立事件逻辑，严禁在没有官方明确共同纪年证据的前提下，擅自把两套时间系统拼成一条绝对编年史。
